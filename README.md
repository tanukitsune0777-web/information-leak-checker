# 情報流出チェッカー（初期版）

スマートフォン向けの静的サイトです。GitHub Pagesで公開し、GitHub ActionsでRSS検索結果を定期収集します。サーバーや有料APIは不要です。

## 重要な制限

- この初期版が自動収集するのは、情報流出関連の**報道・記事候補**です。企業の公式発表だけを完全自動で見分けることはできません。
- 自動で見つけた記事は、すべて「調査中」として表示します。「確認済み」への自動変更はしません。
- 記事タイトルや説明から、会社名・流出件数・対象データを確実に判定できない場合があります。現状は会社名を「記事本文で確認してください」、件数を「未確認」と表示します。
- RSSの配信仕様変更やアクセス制限で収集が止まることがあります。掲載漏れ・重複・更新遅延もあり得ます。
- このサイトは、個人が流出対象かどうかを判定するものではありません。
- 問い合わせフォーム、広告、アクセス解析、個人情報入力欄は初期版にありません。
- GitHub Pagesは公開サイトです。公開リポジトリには個人情報や秘密情報を置かないでください。

## 公開方法（初回だけ）

1. GitHubアカウントにログインします。アカウントがなければ GitHub の公式サイトで作成します。
2. 右上の「＋」→「New repository」を選びます。
3. Repository name に `information-leak-checker` と入力し、**Public** を選んで「Create repository」を押します。
4. このZIPを展開し、中にあるファイルとフォルダーをすべてリポジトリの最上位へアップロードします。`.github` フォルダーも必要です。
   - リポジトリ画面の「Add file」→「Upload files」からアップロードできます。
   - フォルダーをまとめてドラッグできない場合は、GitHubのWeb画面でフォルダーを作るか、GitHub Desktopを使います。
5. 変更を保存（Commit changes）します。
6. リポジトリの **Settings → Pages** を開きます。
7. Build and deployment の Source で **GitHub Actions** を選びます。
8. **Actions** タブを開き、ワークフローが有効になっていることを確認します。「Collect information-leak news candidates」を選び「Run workflow」を押すと手動で一度実行できます。
9. 実行が終わったら **Settings → Pages** に表示される公開URLを開きます。初回公開まで数分かかる場合があります。

## 自動更新

ワークフローは日本時間の午前7時23分・午後7時23分ごろを目安に実行する設定です。GitHub側の混雑で遅れることがあります。最初はActionsタブから手動実行して動作確認してください。

## 表示ステータスのルール

- `確認済み`：公式発表等でインシデントの発生を確認できたもの。個人の影響範囲とは別です。
- `可能性あり`：信頼できる報道等で可能性が報じられているが、公式発表が未確認のもの。
- `調査中`：真偽・影響範囲・件数等を確認中のもの。

現状の自動収集は候補の発見までです。誤認を避けるため、すべて「調査中」として表示します。公式発表を手作業で確認してから `data/incidents.json` の項目を更新してください。

## データ形式

`data/incidents.json` に掲載データがあります。`source_url` は元記事へのリンク、`followup_url` は公式発表や続報ページへのリンクです。件数がわからない場合は `records` を `未確認` にしてください。
